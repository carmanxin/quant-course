### 设计决策

- **不推荐"平台 Git 集成自己构建"**：EdgeOne/Cloudflare 构建容器没有 Python，precompute 跑不了，
  439 个案例的运行结果会全丢。必须让 GitHub Actions（有 Python）构建完再交给平台。
- **precompute 产物策略**：CI 检测 `public/code/*.output.json` 数量 ≥480 就跳过重跑
  （构建 20min → 4min，且结果与本地 100% 一致）；否则装精简依赖重跑，`continue-on-error` 不阻塞。
- **未配 secret 时工作流仍成功**：用 `env.HAS_TOKEN: ${{ secrets.X != '' }}` 做条件跳过，
  方便先验证构建链路再配部署。
- **publish-dist-branch 用独立目录 git init + force push**，不用 orphan 分支（避免残留源码目录）。
  用内置 `secrets.GITHUB_TOKEN`，只需 `contents: write`。

### 🔴 关键网络发现：github.com HTTPS 不通，SSH 通

实测（2026-09-08）：

| 目标 | 结果 |
|---|---|
| `api.github.com` | ✅ HTTP 200 |
| `github.com:443` | ❌ 21s 超时 |
| `git@github.com:22` (SSH) | ✅ 握手成功（Permission denied publickey = 通，只是没钥匙） |
| `baidu.com` / `edgeone.ai` | ✅ 正常 |

nslookup 把 github.com 解析到 `20.205.243.166`，该 IP 的 443 不通（典型国内现象）。

**影响与对策**：
- `gh auth login` 的 device flow 会 POST `github.com/login/device/code` → **必然超时失败**。
  → 不要走 gh 登录，改用「网页建仓库 + SSH push + 网页配 Secret」。
- `git push` 必须走 SSH：`git@github.com:<user>/<repo>.git`
- 已配全局 `url."git@github.com:".insteadOf "https://github.com/"`，
  这样仓库里写 https 的 remote 也会自动走 SSH（撤销：`git config --global --unset url."git@github.com:".insteadOf`）
- 已生成 `~/.ssh/id_ed25519`（无密码，注释 quantlab-deploy），**公钥待用户加到 GitHub**
- 变通：若日后要 gh 登录且 HTTPS 仍不通，可用 `gh auth login --with-token`（浏览器生成 PAT 后喂进去），
  绕过 device flow；gh 的其他命令走 api.github.com，是通的。
