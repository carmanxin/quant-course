## 四、发布与上线核验（续记，14:00–15:10）

### 双端推送复核 —— 勘出两处「假绿」

`origin` 配了**双 pushurl**（GitHub + Gitee），`git push origin` 会同推两端，
但 **tag 不随分支 push 自动过去**。push 回显全绿，实测：

| 引用 | 初始状态 | 处置 |
|---|---|---|
| GitHub 侧标签 | **一个都没有** | 补推 `v1.0.0-pre-fix` / `v1.1.0` ✅ |
| Gitee 侧 `dist` 分支 | **缺失** | 用 `refs/remotes/origin/dist:refs/heads/dist` 补推 ✅ |
| `dist` 旧版锚点 | 强推后**远端失引用** | 新立 `archive/dist-v1.0.0-pre-fix` → `76feba9` ✅ |

**纪律：push 后必须 `git ls-remote <remote> 'refs/heads/*' 'refs/tags/*'` 逐项核对。**

### Gitee dist 分支需强推
CI 的 `publish-dist-branch` 只推 `origin`（GitHub），Gitee 侧 `dist` 停在旧提交。
且 CI 用 **forced update**，所以补推 Gitee 必须带 `--force`，否则报 non-fast-forward：
`git push gitee --force refs/remotes/origin/dist:refs/heads/dist`
⚠️ 本地无 `dist` 分支，只有 `refs/remotes/origin/dist` 远程跟踪引用。
