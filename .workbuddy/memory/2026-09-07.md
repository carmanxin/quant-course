## bat 修复:浏览器只打开 127.0.0.1 不带端口

用户反馈 bat 打开的是 `http://127.0.0.1`,端口 4179 没带上。

**根因**:`start` 打开浏览器是异步的,node 启动需 1-2 秒,浏览器在端口尚未 LISTENING 时就发请求
→ 连接失败 → 地址栏退化成不带端口的形式。

**修复**:启动 node 后轮询等待端口真正 LISTENING,就绪后再打开浏览器(最多等 30 秒,超时给手动提示)。

### Windows 批处理踩坑记录(重要)

1. **`start /b` 开关位置**:应写 `start /b "" node serve.cjs`,不是 `start "" /b node serve.cjs`
2. **`for /l` 在 .bat 里用 `%%i`**;从 bash heredoc 写入时要写 `%%i`(不是 `%%%%i`,bash 不做 % 转义)
3. **`findstr ":4179 "` 的空格陷阱**:findstr 把空格当 OR 分隔符,尾部空格会产生"空搜索词"匹配所有行
   → **必须用 `findstr /C:":4179 "`** 做字面量匹配
4. **端口检测优先用 netstat 而非 curl**:netstat/findstr 是 Windows 自带,curl 在旧系统可能不存在;
   实测 `netstat -ano | findstr /C:":4179 " | findstr "LISTENING"` 可精确匹配且无误报
5. **中文文件名 + Git Bash 调 cmd 会失败**:Git Bash 传 UTF-8 文件名,cmd 按 GBK 解析找不到文件
   → bat 文件名改英文 `start-server.bat`(bat 内容仍用 GBK 编码保存,中文提示正常显示)
6. **测试 bat 时管道会挂起**:`start /b` 的子进程继承 stdout 管道,Python `subprocess.capture_output`
   会一直等。安全策略还禁止从 bash/PowerShell 调 cmd.exe,所以完整 bat 无法自动化验证 ——
   改为分段验证(端口 LISTENING + HTTP 200 + 单独验证 netstat 匹配格式)

### 实测结论

- `where node` 检测通过(否则会 exit /b 1)

## 答疑:1.3 案例2 凯利模拟的中位数/均值数字巨大

用户质疑 `guide/m01-overview/1.3-quant-mindset.md` 案例2(hash `c3b961b1`)
输出的中位数达 6e20 是否算错。

**结论:没算错,数学完全正确。** 验证方法:

```
g(f) = p·ln(1+b·f) + (1-p)·ln(1-f)     p=0.55, b=1.5
理论中位数终值 = exp(n·g), n=1000
```

| f | 理论 g | 理论终值 | 实测中位数 | 判定 |
|---|---|---|---|---|
| 5% | +0.0167 | 1.8e7 | 1.9e7 | 吻合 |
| 25% | +0.0457 | 7.0e19 | 6.1e20 | 同量级 |
| 40% | +0.0286 | 2.7e12 | 1.4e11 | 同量级 |
| 60% | -0.0593 | →0 | 0.001 | 爆仓钳位 |
| 80% | -0.2906 | →0 | 0.001 | 爆仓钳位 |

差异来源:仅 100 条路径的抽样噪声(Binomial(1000,0.55) 标准差 ≈15.7 次胜负)。

**根因**:n_trades=1000 与每笔 +4.6% 对数增长复合 → e^45.7 ≈ 7e19。是参数放大,非 bug。

**真正值得改的 3 点**(用户未要求,已提出待确认):
1. `f"{x:.1f}"` 把爆仓钳位值 0.001 显示成 "0.0x",信息丢失 → 应改用 `{:.2e}`
2. 绝对倍数不可读 → 应补一列「每笔对数增长率 g」和「年化」
3. n_trades=1000 不现实(真实策略年 100~250 笔)→ 建议降到 200
4. 隐藏教学点未点破:f=20% 均值最大(5.7e26)而 f=25% 中位数最大(6.1e20),
   正好演示「最大化期望 ≠ 最大化典型路径」,当前输出没说明

## 清理全站"本段代码定义：函数 xxx()"裸噪音(131 处)

**问题**:SILENT_EPILOGUE 在用户只 def 不调用时,会输出形如
"本段代码定义：函数 multi_asset_trend_following()、函数 cross_exchange_funding_arb()" ——
纯名字罗列,无任何数值结果,既不说明代码意图也无运行结果。全站 503 个输出文件里有 131 个
(占 26%) 落进这种模式。

**根因**:`scripts/precompute-py-outputs.mjs:852` 的静默重跑只看 `r.stdout.trim().length > 10`,
`>10 字符即落进 text 路径`,但 SILENT_EPILOGUE 的"本段代码定义:..."一行足够长(50+ 字符),
所以这些 case 被错误地当作"有真实输出"放进了 text。

**修复**:在 line 854 之后加识别 — 头部是 "本段代码定义:" 且不含 `--- name (type) ---` 数值块
且不含 `--- 结果 ---` 自动摘要时,跳过 silent 重跑,让 case 自然落到下面的 `isFragment` 分支
(走 fragment note)。`isFragment` 已含 `(hasDefOrClass && !hasModuleLevelCall)`,所以
原本就该走 fragment,只是被 silent 重跑劫持了。

**效果**:裸字符串 131 → 0;蓝色 fragment note 路径从 142 → 273(全部 503 个里有 273 个
本来就只 def 不调用,全部走友好提示);0 个 "⚠ 暂无运行结果"。
组件 `StaticCodeBlock.vue` 的 `describeFragment()` 会自动解析 def 上面的 docstring,
显示成 "📘 本段代码定义了 1 个函数/类:函数 `run_backtest`(完整的回测主循环,模拟逐日交易流程)。
该片段为教学展示...",比裸字符串友好得多。
