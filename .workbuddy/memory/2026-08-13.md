## 关键发现：VitePress dev 模式也会跑 SSR fence 钩子

之前以为 `vitepress dev` 是纯客户端渲染（curl 返回 423 字节空壳 HTML），
实际上 markdown-it fence 钩子仍然在**服务端**运行，把 `outputB64` 写到组件 prop。
所以修改 `public/code/*.output.json` 后，必须**重启 dev server** 才能生效，
浏览器刷新或加 cache-bust 参数都不行，因为 base64 已经硬编码进 JS bundle。

## 验证 1.1-history.html

- 案例1 (yfinance) 和 案例2 (networkx) 都显示友好的蓝色 note：
  `📘 本脚本依赖外部模块 \`xxx\`（未在预计算环境安装，无法独立运行；安装后可重跑 precompute）`
- 不再是 raw Traceback。

## 调试路径

1. agent-browser 加载页面 → DOM 显示 `scb-out-error`
2. curl `/code/a3c5ea31.output.json` → 返回 `note`
3. 浏览器内 `fetch('/code/a3c5ea31.output.json')` → 也返回 `note`
4. 检查 Vue 实例 `props.outputB64` → **base64 解码后是旧的 error 数据**
5. 结论：dev server 内存里仍是旧 `.output.json` 的 inline 副本
6. 解决：`taskkill /F /PID <pid>` 然后 `npx vitepress dev --port 5188`

## 镜像安装外部模块：真实输出率从 22% → 63%

用户提议通过国内镜像安装外部模块。配置 + 跑通：
- `pip config set global.index-url https://mirrors.aliyun.com/pypi/simple/`
- `pip config set global.trusted-host mirrors.aliyun.com`
- `python3 -m pip install yfinance networkx statsmodels arch hmmlearn vectorbt akshare pyarrow polars lightgbm xgboost numba msgpack prometheus_client websockets`
- `PRECOMPUTE_INSTALL=1 node scripts/precompute-py-outputs.mjs` 跑 19 分钟：372/462 成功
- patch-errors-to-notes 把剩余 error 转 note
- 重启 dev server

**重要**：`spawn('pip', ...)` 在 PATH 里 pip 指向 Python 3.14，但 `python3` 是 3.13。
手动 `python3 -m pip install` 才是正确的（装到 3.13 site-packages）。
脚本里应该用 `python3 -m pip` 而非裸 `pip`。

## matplotlib 中文字体修复

原本脚本生成的 SVG 里中文显示为方块（font fallback 失败）。
在 `scripts/precompute-py-outputs.mjs` 的 preamble 里加：
- 候选字体路径：msyh.ttc / simhei.ttf / simsun.ttc / NotoSansCJK / wqy-microhei / PingFang
- `font_manager.fontManager.addfont()`
- `rcParams['font.sans-serif'] = [实际字体名, 'DejaVu Sans']`
- `rcParams['axes.unicode_minus'] = False`

效果：1.1 案例1 的 "全球主要指数累计收益对比" 标题、坐标轴、图例全部正常显示中文。
