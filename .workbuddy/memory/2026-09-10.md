## Cloudflare 构建调试（仍走 Git 集成界面路线 / 方案 A）

### 现象
用户贴了两份构建失败日志（9/8 11:20 与 9/10 08:54），**错误完全相同**：
```
npm error code EUSAGE
npm ci can only install with an existing package-lock.json ...
```
Build command 两次都是 `npm ci --ignore-scripts && npx vitepress build`。

### 根因（已确认）
Cloudflare 项目拉的**分支是 `dist`**，不是 master。
- `dist` 分支由 GitHub Actions 用 `git init + git add -A`（仅 `.vitepress/dist` 产物）强推生成，
  **不含 `package.json` / `package-lock.json`** → `npm ci` 必然 EUSAGE。
- master 分支已确认：`package-lock.json` 既没被 .gitignore 排除、也已 `git ls-files` 跟踪。
- 用户最早按 9/8 旧建议把分支配成 dist，新版 Workers Builds 界面**创建后无 Production branch 编辑项**，
  所以一直锁在 dist。

### 修复（走 A：界面）
1. 分支改回 `master`：Settings → Builds & deployments → Production branch 改成 master；
   **若那里也改不了，删项目重建，创建时 Branch 选 master**（别选 dist）。
2. Build command 改成（用 `npm install` 而非 `npm ci`，不依赖 lock 在场）：
   `npm install --ignore-scripts && npx vitepress build`
3. Save and Deploy / Retry deployment。

### 备选（走 B：Actions 自动部署，用户本次未选）
Cloudflare 界面零配置，由 `deploy-cloudflare` job 用 Wrangler 推。需 GitHub 加 Secret：
`CLOUDFLARE_API_TOKEN` + `CLOUDFLARE_ACCOUNT_ID`（项目名非 quantlab 再设 `CLOUDFLARE_PROJECT`）。
两条路二选一，不能并存。
