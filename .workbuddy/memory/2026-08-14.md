## scaffold 调用顺序 bug + 案例编号修正

### Bug 现象

用户反馈 1.2 里：
- 案例2 (均线策略): 输出里有 `--- moving_average_crossover(...) --- 调用失败: name '...' is not defined`
- 案例2 (配对交易) 显示 note "脚本运行成功但无 print 与图表输出"，且**标题重复**（应该是案例3）

### 根因 1: scaffold 调用时机错误

`buildScaffold()` 把"自动调用 def"生成的代码放在用户代码**之前**。但 def 本身在 wrapped user code（try 块内）才执行，所以在调用 def 时 def 还没注册到模块作用域 → NameError。

修复：把 `buildScaffold` 的输出拆成两段
- `pre`: imports + demo 数据（放在用户代码**前**）
- `post`: 自动调用 def（放在用户代码**后**）

此时 def 已通过 `try: def foo(): ...` 注册到模块作用域（Python 语法允许 def 在 try 中定义后从外部调用），post 代码可以正常调用。

### 根因 2: hasModuleLevelCall 误判

`hasModuleLevelCall` 的正则 `/^\s*[A-Za-z_]/` 允许前导空格，把函数体内缩进的 `n = prices_df.shape[1]` 误判为模块级调用。结果 `isFragment = false`，scaffold 不注入 → 配对交易的 def 只定义不调用，stdout 为空。

修复：要求正则必须从第 0 列开始（`/^[^ \t]/`），只把真正的顶层语句算作模块级。

### 根因 3: 1.2 标题重复

第二个 "### 案例2：配对交易信号生成与回测" 应是 "### 案例3"，因为前面已经有案例1 (趋势信号) 和案例2 (均线策略)。

## 1.4 案例2 CostSimulator 输出修复

### 用户报告的问题

```
--- __init__(...) --- 调用失败: name '__init__' is not defined
--- compute_costs(...) --- 调用失败: name 'compute_costs' is not defined
--- 结果 ---
commission_rate = array([ 0.6969544 , -0.33381949, ...])  ← 垃圾变量注入
stamp_tax_rate = array([...])                              ← 垃圾
impact_model = array([...])                                ← 垃圾
```

### 根因（buildScaffold 三处缺陷）

1. **类方法被当独立函数调用**：`/^\s*def\s+/` 正则匹配了类内缩进的方法（`__init__`/`compute_costs`），自动调用失败
2. **类体变量被误分析为外部依赖**：`self.commission_rate = commission_rate` 这类行被 used 分析收集 → 注入 `np.random.randn(100)` 垃圾
3. **hasModuleLevelCall 误判**：函数体内缩进的 `n = prices_df.shape[1]` 被当模块级调用

### 修复（scripts/precompute-py-outputs.mjs）

1. **class 缩进状态机**：进入 class 块后跳过其缩进体内所有行（`classIndent` 变量）
2. **post 只调模块级 def**：正则 `/^def\s+/`（第 0 列），类方法不调用
3. **恢复函数参数 declared**：模块级 def 的参数进 declared，函数体内引用不算外部依赖
4. **RHS 过滤增强**：
   - `\b[rf]?"[^"]*"` 去掉 f-string 前缀 f
   - `\.\w+` 去掉属性访问名（`.values`/`.columns`/`.iloc`/`.shape`）
   - `\b[A-Za-z_]\w*(?=\s*=)` 去掉关键字参数名（`commission_rate=`）
5. **纯 def 片段不注入**：`isPureDefOnly = hasDefOrClass && !hasModuleLevelCall`，这些片段跳过 scaffold → 显示 fragment note（1.2 均线/配对交易符合预期）
6. **payload 判定改为 hasRealOutput 优先**：fragment 若有真实 print 输出则保留，不再强制 note（修复 300106fc 等）
7. **preamble 常备 numpy/pandas**：`import numpy as np, pandas as pd`，教学片段常假定上下文已有（修复 0578730b 等）
8. **`_df` 后缀注入 DataFrame**：returns_df 等匹配 DataFrame 注入分支

## fragment note 智能阐释 + 代码折叠（用户 UI 需求）

### 需求
1. "本段为代码片段（仅展示函数/类定义，未提供运行入口，无需运行）" note 太生硬，应阐释该段代码的目的
2. Python 代码折叠，明确提示"此处有展示代码"

### 实现（components/StaticCodeBlock.vue）

**1. 代码折叠**
- `.scb-code` 包进 `<details class="scb-code-wrap">`
- summary 显示 "📄 此处有展示代码 N 行 · 大小 展开 ▼"
- 默认收起（`codeOpen = ref(false)`），`@toggle` 同步状态
- 深色模式补充样式

**2. fragment note 智能阐释**
- 组件内 `describeFragment(code)` 函数：
  - 提取模块级 def/class 名（第 0 列，类内方法如 __init__ 不列出）
  - 提取 docstring 首行（支持跨行签名、多行 docstring、单引号/双引号）
  - 提取紧跟的 # 注释
  - 过滤 Parameters/Returns/Args 等文档标记行
  - 截断到 60 字
- `noteText` computed：当 note === FRAGMENT_NOTE 时生成阐释，否则原样
- 227 个 fragment 全部有描述（有 docstring/注释的 ~90%+）
