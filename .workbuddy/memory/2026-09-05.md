# 2026-09-05 工作日志

## 交付「单文件离线 HTML」(用户核心诉求)

### 背景
用户反馈:每次完工给的 `http://127.0.0.1:4179/` 内网地址,在没有后台运行环境时打不开。
需要**双击即可访问**的 HTML 文件。

### 关键发现:便携版为什么双击打不开
- `portable/dist/` 里确实有 120 个 HTML,但 VitePress 产物用了 `<script type="module">` + fetch
- Chrome/Edge 在 `file://` 协议下**严格禁止** ES module,所以必须起 HTTP 服务

### 体积评估(决定方案可行性的关键)
| 项 | 体积 | 是否必需 |
|---|---|---|
| 117 页正文(SSR 后) | 18.3 MB | 必需 |
| SVG 图 | 2.6 MB(27 个文件) | 必需 |
| output.json | 0.1 MB | **已 SSR 进 HTML,不需单独内联** |
| `public/code/*.py` | 16 MB(3477 个) | **不需要**(构建产物复制过去的源码) |
| CSS | 155 KB | 必需 |

→ 产出 **19.2 MB** 单文件,完全可接受

### 实现:scripts/build-single-html.py
1. 提取每页正文:`class="vp-doc"` 的 div 起点 → `</main>` 终点
2. **内联 SVG**:`<img src="../../code/xxx.svg">` → base64 data URI(23 张全部内联)
3. **内联 CSS**:`assets/style.*.css` + `vp-icons.css`
4. **懒渲染**:117 页正文放 `<template id="pg-N">`(不进渲染树、不加载图片),
   点目录时才 `main.innerHTML = tpl.innerHTML`
5. 侧边栏按目录分组自动生成,hash 路由

### 踩坑记录(重要)
1. **template id 错位 bug**:`templates` 排序后,`id="pg-N"` 仍是排序前下标,
   而 JS 用数组下标取 → 点 A 章渲染出 B 章。
   修复:排序后统一 `re.sub(id="pg-\d+" → id="pg-{i}")` 重新编号
2. **零宽空格残留**:`extract_title` 里 `.replace('','')` 写成了空串(源码里 U+200B 被吞),
   必须用 `'\u200b'` 显式转义
3. **自然排序 TypeError**:`[int(t) if t.isdigit() else t ...]` 混排 int/str 会崩,
   改成 `(1, int(t), '') / (0, 0, t)` 三元组包装

### 使用
```bash
python scripts/build-single-html.py   # 或 npm run offline
# 输出:QuantLab-离线单文件.html (19.2 MB, 117 页)
```

### 验证结果
- template 117 个,id 严格递增 0..116,与 PAGES 下标对齐
- 外部依赖残留(外部 script/css/绝对路径 img):**全部 0**
- 23 张图全部 base64 内联,零外链
- 2234 个运行结果折叠块完整保留
- 标签配对:template/aside/main/script/style/body/html 全部 OK

## 修复"格式与线上不一致"的反馈

### 用户反馈
"quantlab离线HTML文件中呈现的内容和http://127.0.0.1:4179/ 里呈现的内容不一样啊,主要是格式上的"

### 诊断方法
- `scripts/_cmp-shot.mjs` 用 playwright 截图线上版 vs 离线版同页(1.7)对比
- 阅读两张截图直接定位差异

### 发现 3 个差异
1. **侧边栏分组标题全错**(致命):用每页 sidebar 第一个 `<h2>` 作组标题,但 sidebar 第一个永远是 M01,导致 4 个分组都叫"模块一"
   - 修复:取带 `has-active` 的 section 的 `<h2>`(当前页所在的模块)+ fallback 目录名映射表

3. **正文贴左、留白全没**:提取时丢了 `.VPDoc` / `.content-container` 链式选择器的外层容器样式
   - 尝试给 main 加 `.VPDoc` class — 无效(VitePress CSS 假设特定父结构,与我自定义 wrap flex 冲突)
   - 改方案:自己控制布局,新增 `.content-wrap` 包内容 + EXTRA_CSS 直接设 max-width/padding/line-height

### EXTRA_CSS 关键样式
- `.content-wrap { max-width: 860px; margin: 0 auto; padding: 36px 56px 140px; font-size: 15px; line-height: 1.7; }`
- `h1: 34px 绿色 #00b96b` (与线上主题色一致)
- 自定义容器 tip/info/warning/danger 配色与图标,与 VitePress default 主题对齐

### 验证后剩余差异
- 顶部 VPNav 栏(线上独有)
- 右侧本页目录锚点列表(线上独有)
- 这两项属于 VitePress 站点骨架,不影响内容呈现,可后续按需加

### 辅助工具:scripts/_cmp-shot.mjs
playwright 截图脚本,接受 URL 列表生成对比图,留着以后调样式时直接复用
