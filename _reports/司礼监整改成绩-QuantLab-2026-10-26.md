## 二、第一令 · 堵住产物覆盖漏洞

### 2.1 所修之处

`scripts/precompute-py-outputs.mjs` 三处裸 `writeFile` 全部收归守门：

```js
function scorePayload(p) {
  let s = 0
  if (p.text.length >= 30) s += 40
  else if (p.text.length >= 8) s += 30
  else if (p.text.length >= 1) s += 10
  if (p.svgs.length > 0) s += 25
  if (p.note) s += 10
  if (p.error && !p.text) s -= 30
  // scaffold 空壳再 -20
  return s
}
```

守门三态：

- **新优旧劣 → 覆盖**（主动重跑能刷新结果）
- **新劣旧优 → 保留旧**（重跑不降级既有优质产物）
- **同分 → 以新覆盖旧**（保证重跑有更新能力）

### 2.2 SVG 目录一并纳入保护

**原案有疏漏**：只护 JSON 不护 SVG 目录，会致「旧 text 配新图」两者不自洽。
已补 `backupSvgDir` / `restoreSvgDir`，且**按 name 索引**（`Map`）——
预计算并发 8 任务，模块级单变量会互相覆盖导致恢复错乱。

### 2.3 验收

**双向实测**（端到端调用 `writePayloadGuarded`）：

```
A 低质量旧 + 优质新 → keptOld=false   （已覆盖）✓
B 高质量旧 + 低质量新 → keptOld=true    （保留旧）✓
  保留后内容长度: 23                    （真实内容完好）✓
```

**原始案卷复验**（`6136496a` 依赖 akshare 拉真实行情，需 45 秒，默认超时 30 秒必被 SIGKILL）：

```
PRECOMPUTE_ONLY=6136496a → kept-old=1
产物 text 仍为 608 字符，git status 零变更
```

**打分分档实测**：

| 载荷 | 分 | 判 |
|---|---|---|
| 真实长输出(608 字) | 40 | 真实 |
| 真实短输出(19 字) | 30 | 真实（**初版 30 字阈值误判为 0 分，已改为分级计分**） |
| 极短输出(3 字) | 10 | 弱 |
| note 兜底 | 10 | 诚实回落 |
| 空 + error | −30 | 失败 |
| SVG 图表 | 65 | 最佳 |
| scaffold 空壳 | 30 | 弱（已额外扣分） |

> **遵行途中自纠**：初版守门以「≥30 字」一刀切，导致 19 字符的真实输出得 0 分、
> 低于 note 的 10 分，**优质反被劣质拦下**。改为分级计分后修正。

## 三、第二令 · 修正 CI 阈值悖论

### 3.1 旧判据之弊（原文照录）

`ls public/code/*.output.json | wc -l >= 480` —— 而一轮全新 precompute 的产出上限
就是唯一 fence 数 **439**。阈值永远达不到；仓库之所以"够数"，靠的是 **145 个孤儿产物在凑**。

### 3.2 新判据（索引完整性，三条件与立）

```yaml
INDEX_N = _index.json 条目数
FENCE_N = md 中唯一 python fence 数（与 extract 同口径）
MISSING = 索引条目中无对应产物文件的个数

if INDEX_N > 0 且 INDEX_N == FENCE_N 且 MISSING == 0 → 跳过 precompute
```

新增 `scripts/count-unique-fences.mjs`（独立脚本文件）：
bash 内联 `node -e` 的 `\$` 转义地狱致 FENCE_N 算成 0，独立成文件方得可靠。

### 3.3 验收（三情形推演 + 实测）

| 情形 | INDEX_N | FENCE_N | MISSING | 判定 | 期望 |
|---|---|---|---|---|---|

| 索引缺 3 条 | 436 | 439 | 0 | 不跳过 | ✓ |
| 产物缺 1 个 | 439 | 439 | 1 | 不跳过 | ✓ |

**孤儿产物清理终检**：


## 五、🔴 自劾：前次鉴定两处误判

遵行途中，本官发现**前次鉴定书有两处结论有误**，据实自陈。

### 5.1 误判一：「`QuizBlock.vue` 已删除」—— **不实**

实查 git `f264546`：组件文件**一直存在**，且与 HEAD 逐字节一致；
`theme/index.ts` 也**从未删除**注册行。前次鉴定书 §3.7「组件已删除」之记载，
系本官**只看了工作区状态、未回溯 git 历史**所致误断。

### 5.2 误判二：「13 个页面测验内容丢失」—— **系验证脚本自身的假阴性**

前次验证脚本 grep 的是 `QuizBlock` / `question-b64` / `quiz-option`。
然 **Vue SSR 后，组件名与自定义 prop 均不出现在 HTML 中**，产物实际形态是：

```
qz-head / qz-badge / qz-opt--idle / qz-opt-body
```

故「测验丢失」纯属**量尺刻错**，产物一直正常。实测 13 个页面：
m11 每页 3 题全渲染、m20 每页 1 题全渲染，选项 132/132 零偏差。

### 5.3 误判之代价与补偿

前次鉴定据此判「config.ts 的转换逻辑成死代码，应删或恢复组件」——
**若照此令行，反会把能用的转换逻辑删掉**。幸本官遵行时先复验产物，
方察此节有伪。**幸未酿成事故。**

> **本官立此为鉴：凡断「某物已亡」者，必先溯 git 历史；凡断「某物未现」者，必先核产物真实形态，
> 不得以量尺之误妄言对象之亡。**

### 5.4 遵行途中真正勘出之要害（第一轮漏查者）

前次鉴定书未察、而本次遵行方才暴露的真问题：

> `.vitepress/theme/index.ts` 中 `import QuizBlock` 与 `import RunLocally` 均存在，
> 然对应的 **`app.component(...)` 注册行缺失**。
> 未注册的自定义元素在 SSR 阶段被当作未知 HTML 元素，Vue 不予渲染 ——
> **内容在产物中直接消失，且构建零报错**。

| 组件 | 状态 | 影响 | 修复 |
|---|---|---|---|
| `RunLocally` | 只 import 未注册 | **12 个页面**的「本地运行/Colab」提示条整条消失 | 已补注册 |
| `QuizBlock` | 只 import 未注册 | 13 个页面的测验交互态降级为静态文本 | 已补注册 |

> 注：`QuizBlock` 补注册后，13 页测验**外观本就正常**（SSR 已渲染），
> 补注册的意义在于**恢复 Vue 组件的响应式与客户端交互**（点选判对错、显示解析）。
> 而 `RunLocally` 补注册的效果是**内容从无到有**——这才是本次真正救回的东西。

### 5.5 顺带补正的一处误判

前次鉴定书 §3.7 记「`RunLocally` 11 处」——实际为 **12 个页面**。
（`grep -rc "<RunLocally" guide/` 实测；差异源于前次统计含重复计数。）
